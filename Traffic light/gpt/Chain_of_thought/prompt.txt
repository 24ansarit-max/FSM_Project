I want you to design a parameterized 4-way (cross) intersection traffic light controller FSM in synthesizable SystemVerilog.
Before writing any RTL, think through the design step by step:

1. Identify all inputs and outputs (clk, rst, emergency_vehicle, fault_detect, pedestrian_request[3:0], light_N/E/S/W[2:0], pedestrian_walk[3:0], state display) and parameters (CLK_FREQ_HZ, GREEN_TIME_SEC, YELLOW_TIME_SEC, ALL_RED_TIME_SEC).
2. List all states: N_Green, N_Yellow, E_Green, E_Yellow, S_Green, S_Yellow, W_Green, W_Yellow, All_Red, Fault_Flash.
3. Define the phase sequence and transition conditions:
   - How does the FSM cycle N -> E -> S -> W -> N?
   - How does the All_Red clearance interval fit between each yellow and the next green, and how does the FSM remember which approach is next?
   - What triggers each transition (timer expiry, emergency, fault)?
4. Define the timing logic: the cycle count for each phase derived from CLK_FREQ_HZ and the *_TIME_SEC parameters, the timer counter width using $clog2, and when the timer resets.
5. Define the output encoding for each state (which approach is Green/Yellow/Red) and prove that no state ever produces two green outputs at once.
6. Identify corner cases: emergency vehicle asserted mid-green or mid-yellow (must the yellow be completed before going all-red?), emergency released while in override, fault_detect asserted in any state, pedestrian request arriving just before the green ends, rapid toggling of emergency_vehicle, reset while in any state, and the first cycle after reset (should it start at All_Red for safety?).
7. Define reset behavior (synchronous reset, start in All_Red or Fault-safe state, timer cleared, all pedestrian walk signals off).
8. Only after completing the above steps, generate the synthesizable SystemVerilog RTL implementing this controller.

Show your reasoning for each step before presenting the final RTL code.
