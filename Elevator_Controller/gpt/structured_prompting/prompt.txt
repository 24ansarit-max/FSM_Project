Generate Verilog RTL code for a hardware module based on the structured specification below.

### Module Specification
- Module Name: elevator_controller
- Parameters:
  | Name         | Default | Description                     |
  |--------------|---------|----------------------------------|
  | NUM_FLOORS   | 4       | Number of floors served          |
  | TRAVEL_CYCLES| 10      | Clock cycles to move one floor   |
  | DOOR_HOLD    | 5       | Clock cycles door stays open     |

### Ports
| Name           | Direction | Width               | Description                          |
|----------------|-----------|---------------------|---------------------------------------|
| clk            | input     | 1                   | System clock                          |
| rst_n          | input     | 1                   | Active-low async reset                |
| floor_request  | input     | NUM_FLOORS          | One bit per floor call button         |
| door_obstacle  | input     | 1                   | High if door sensor detects obstacle  |
| motor_up       | output    | 1                   | Drive elevator up                     |
| motor_down     | output    | 1                   | Drive elevator down                   |
| door_open_out  | output    | 1                   | Door open drive signal                |
| door_close_out | output    | 1                   | Door close drive signal               |
| current_floor  | output    | $clog2(NUM_FLOORS)  | Current floor index                   |
| state_out      | output    | 3                   | Current FSM state (debug)             |

### FSM Table
| Current State | Condition                                   | Next State   |
|----------------|---------------------------------------------|--------------|
| IDLE           | request pending above current floor         | MOVING_UP    |
| IDLE           | request pending below current floor         | MOVING_DOWN  |
| MOVING_UP      | current_floor == target and counter done    | DOOR_OPEN    |
| MOVING_DOWN    | current_floor == target and counter done    | DOOR_OPEN    |
| DOOR_OPEN      | hold timer expired and no obstacle          | DOOR_CLOSED  |
| DOOR_CLOSED    | requests remain in same direction           | MOVING_UP/DOWN |
| DOOR_CLOSED    | no requests remain                          | IDLE         |

### Internal Registers Required
- request_reg [NUM_FLOORS-1:0] : latched pending requests
- direction_reg : 1 = up, 0 = down (last direction, for SCAN algorithm)
- travel_counter : counts cycles for floor-to-floor movement
- door_counter : counts cycles for door hold time

### Design Rules
1. Use Moore-style FSM: outputs depend only on current state.
2. Use two always blocks: one for sequential state/register update (posedge clk or negedge rst_n), one for combinational next-state and output logic.
3. Requests must be serviced using a SCAN (elevator) algorithm — continue in current direction until no more requests ahead, then reverse.
4. All state encodings must use localparam.
5. Code must be fully synthesizable (no delays, no non-blocking violations, no latches).

### Deliverable
Output the complete Verilog module matching the tables and rules above exactly, with inline comments mapping each code section back to the FSM table.
